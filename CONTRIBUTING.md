# Contributing

Thanks for taking the time to report a bug or suggest an improvement.

## The simple version

- Anyone may **read** the public source.
- Anyone may **fork** the repository and experiment in their own copy.
- Anyone may **open an Issue** or **Pull Request** to propose a change.
- A Pull Request is only a proposal. It does not change the official `main` branch unless the maintainer accepts and merges it.
- Do not ask for direct collaborator/write access just to submit a fix; use a Pull Request instead.

## Bug reports

Please include:

- Flight Map Tools version.
- Operating system.
- What you were trying to do.
- What happened instead.
- The exact error/status text when practical.
- A minimal sanitized sample only if it is needed to reproduce the problem.

**Do not post private GPS/home/launch coordinates, API credentials, passwords, or other sensitive data.** Flight logs frequently contain precise location information.

## Pull requests

1. Fork the repository.
2. Create a branch for the fix or feature.
3. Keep the change focused.
4. Test the Python source before submitting.
5. Explain what changed and why in the Pull Request.
6. Wait for maintainer review.

The maintainer may accept, request changes, or decline a Pull Request.

## Generated files

Please do not include personal telemetry logs or generated HTML/GPX/KMZ outputs in a Pull Request unless the maintainer specifically asks for a sanitized example.

## Versioning

Normal development should happen without replacing old GitHub Releases. When a public update is ready, the maintainer creates a new version/release.
